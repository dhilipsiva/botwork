# Retained Calls and Handler Diagnostics

`RunLimits::retained_diagnostics` (`core::run::RetainedDiagnosticLimits`) bounds live active-call, handler-error, and admitted outgoing diagnostic records. Defaults permit 65,536 records, 16,384 diagnostic nodes, 65,536 call frames, 65,536 related locations, 32 MiB of raw detail/context text, and 32 MiB of distinct source text/names. Every quota permits zero and explicit increases.

## Counting and Admission

An active call contributes one record, one call frame, its signature's UTF-8 bytes, and its call/definition sources. A handler contributes one record and its complete diagnostic tree, using the [diagnostic ownership metrics](diagnostic-ownership.md). Its captured call frames count separately from currently active calls because they own separate metadata. Raw error text counts occurrences even when error identities are shared. Source allocations are deduplicated by Arc identity across all live records; equal text in distinct allocations counts twice. Source bytes include full filenames and contents without scanning positions.

Admit calls after required argument evaluation and parameter preparation, before copying the signature or entering the callee. An argument's completed effects survive a later call-record rejection. Existing depth/signature checks retain their earlier order. Admit handler errors before building Catch metadata or installing the temporary binding. Measure admitted per-tree diagnostics without copying strings; reserve all aggregate dimensions and source references atomically with checked arithmetic. Failure consumes no capacity.

Quota failure returns BW8001 and latches the requesting Context, bypassing Catch. Rejected handler storage preserves the original category, bounded byte-location evidence, and explicit omissions using the independent [emergency representation](diagnostic-ownership.md#owned-admission-and-emergency-evidence). Observe cancellation/deadlines before attempting admission; a stopped handler retains its original error as bounded evidence beneath the control failure.

## Sharing and Release

Context clones and isolated module contexts share immutable call records. Context clones also share stored handler errors. Their reservations remain charged until the last record owner disappears. Source charges release after the last record referencing that allocation disappears. Separate Engine runs have independent trackers; Context clones share live capacity while keeping independent stop/work state, and module execution shares both.

[Snapshot admission](snapshot-limits.md) counts each copied call/handler handle as an entry. Infallible host Clone stays outside snapshot-work admission. Sharing payloads avoids repeating signature strings, cause trees, and source records for each snapshot; it does not bound the number of host copies.

Release calls and handlers on normal completion, return, error, and observed stop. Restore prior Catch bindings after handler failure. When an error leaves a handler, move uniquely owned metadata into the outgoing diagnostic without requiring another record. If a Context snapshot still owns the record, admit the complete copied tree while its shared reservation stays live. Rethrow also requires copy headroom and includes the new `rethrow` related location and source in admission before copying either payload. For a single stored error with no active calls, rethrow therefore requires two records even though the surrounding handler later releases its original.

An internal outgoing-error carrier keeps each retained or copied record's reservation through expression/statement/call unwinding, imports, cancellation wrapping, and Engine result export. All six aggregate dimensions are reserved atomically, with distinct source owners deduplicated across the original and copy. The prospective copied tree must also fit individual diagnostic limits. Copies share immutable error/source identities while independently owning mutable metadata. Concurrent Context clones compete for the same copy headroom, and only the requester latches a quota failure. Observe cancellation before copy admission.

On rejected rethrow admission, summarize the borrowed original directly; do not clone it to construct the summary. Preserve its category and byte evidence and count the omitted new related site. On rejected handler-unwind copying, preserve the new primary handler failure as bounded evidence and count the omitted original cause. An outgoing error with the same immutable error identity already contains the rethrow evidence and needs no duplicate cause copy. Existing emergency errors increment omitted-cause evidence without copying the retained tree.

## Outgoing Ownership and Handler Re-entry

Moving a retained tree into an outgoing cause transfers its reservation too; cause attachment consolidates the complete combined tree into one record before growing the cause vector. Moving a copy out of Rethrow retains the copy reservation after its original handler disappears. These records stay charged while the internal error is alive, including when another Context clone is executing. Mapping the diagnostic through source/call admission preserves those reservations; a bounded emergency replacement disposes the original metadata before releasing them. Discarding an internal error uses iterative disposal, including raw host trees that have not yet passed individual admission.

When an outer Catch stores the complete outgoing tree, replace its prior reservations atomically with one handler record. Measure the complete tree, preserve unrelated live records, and reconcile source-reference counts before committing any changes. Existing reservations provide capacity for the transferred payload; no artificial duplicate-record headroom is required. Failed replacement leaves old reservations unchanged until the rejected payload is disposed. Source replacements release removed identities before checking new identities, independent of hash iteration order. An explicit local one-record allowance can therefore handle `Try { Try { Missing } Catch { Other } } Catch {}` when two diagnostic nodes fit.

Public statement, program, Pair, and Engine results transfer Diagnostic ownership to the host and release internal charges. Engine retains the carrier through variable-export checking/copying, including failed exports. Public Diagnostic fields, clone behavior, and result types remain unchanged. Holding public results does not retain runtime reservations.

## Outgoing Cause and Related-Location Admission

Internal outgoing errors measure the complete prospective tree before appending a cause or copying an import-related label/span. This applies to handler failures, cancellation wrapping, module initialization, imported calls, and other errors crossing load boundaries. Both individual and aggregate limits apply, including the appended subtree's increased depth. Source identities are deduplicated across both trees and the prospective site. Raw incoming errors acquire their first outgoing reservation at this mutation boundary; already reserved inputs contribute their capacity to one atomic replacement. Moving a cause needs no duplicate payload headroom. Unrelated live records remain charged, and concurrent Context clones compete for the same capacity.

Admission precedes the related string copy and vector insertion, or the cause-vector insertion. On rejection, dispose both inputs iteratively before releasing their reservations. Preserve the current primary category and byte-location evidence beneath the limit error; count the rejected site/cause explicitly. Subsequent emergency mutations only increment omission counts. Duplicate error identities still skip cause attachment. Observe cancellation/deadlines before a new quota can latch; an observed cancellation/timeout stays primary when its additional evidence cannot fit. Normal unwinding performs any remaining stop wrapping.

These checks run even when no outer Catch stores the error. For example, with one record and one diagnostic node, `Try { Missing } Catch { Other }` fails with the retained-node limit and bounded `Other` evidence, including one omitted cause. Two nodes retain the full `Other` error with `Missing` as its cause. No second record is required for this move. Likewise, a two-level failing import requires two related locations even if its error goes straight to the host.

This boundary measures ownership present at the mutation point. Initial constructors and later source/call-stack attachment remain separate pending aggregate-admission paths. The public Diagnostic methods retain their existing host ownership contract.

## Scope and Evidence

These are logical retained-record and copy-admission limits, separate from individual runtime-error quotas and temporary Catch-value storage. The outgoing carrier preserves reservations acquired by handler storage, copies, and cause/related-location mutation admission. Initial message construction, raw errors that never cross those boundaries, and later span/call-stack additions still need aggregate admission before construction; their existing individual quotas apply, and later handler storage or outgoing mutation admits the complete tree. Cause assembly inside the raw diagnostic constructors also retains that pending construction boundary. Host-retained results, standalone NativeOperation errors, allocator overhead, formatting, and output have separate contracts. These quotas establish neither a process-memory ceiling nor a hard deadline.

Unit and integration checks cover every dimension, overflow/atomicity, concurrent capacity, source identity/lifetime, snapshot sharing/handle charges, nested handlers, complete causes, rethrows, imported calls, argument effects, clone stops, fresh Engine runs, and cleanup. Allocation observations verify rejection before large signature and Catch-detail copies. R19 host corpus cases and an executed Rust example pin handler reservation behavior.

Copy admission adds six unit checks for exact/one-less aggregate dimensions, prospective individual related-site limits, unique/shared ownership, concurrent copies, actual Context snapshot retention, primary-error evidence, duplicate identities, cancellation, and cleanup. Two integration checks cover rethrow headroom, prior effects, restored bindings, repeated caught failures, and independent clone stops. An allocation comparison observes zero additional large metadata copies on rejection and one on accepted rethrow. Two additional R19 cases and an executed Rust example pin the two-record boundary.

Outgoing lifetime coverage adds eight unit checks for atomic merging/replacement, all quota failures and overflow, source identity reconciliation, concurrent Context pressure, import unwinding, cancellation summaries, Engine export failure, public transfer, and 100,000-level raw-error disposal. Existing runtime/handler/CLI/allocation matrices remain active. Two R19 handoff cases pin one-record re-entry and complete merged-tree rejection.

Mutation admission adds five unit checks for prospective tree/source/depth measurement, every aggregate dimension, exact replacement credits, unrelated ownership, concurrent Context pressure, cancellation priority, omitted metadata, public transfer, and 100,000-level rejected causes. Two integration checks pin uncaught handler failure and nested-import publication without outer Catch admission. Earlier R19 cases, runtime stop/timeout matrices, import construction, snapshot, and ownership checks remain active.
