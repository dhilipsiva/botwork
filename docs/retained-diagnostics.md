# Retained Calls and Handler Diagnostics

`RunLimits::retained_diagnostics` (`core::run::RetainedDiagnosticLimits`) bounds live active-call, handler-error, and outgoing diagnostic records at synchronous evaluation boundaries. Defaults permit 65,536 records, 16,384 diagnostic nodes, 65,536 call frames, 65,536 related locations, 32 MiB of raw detail/context text, and 32 MiB of distinct source text/names. Every quota permits zero and explicit increases.

## Counting and Admission

An active call contributes one record, one call frame, its signature's UTF-8 bytes, and its call/definition sources. A handler or admitted outgoing error contributes one record and its complete diagnostic tree, using the [diagnostic ownership metrics](diagnostic-ownership.md). Its captured call frames count separately from currently active calls because they own separate metadata. Raw error text counts occurrences even when error identities are shared. Source allocations are deduplicated by Arc identity across all live records; equal text in distinct allocations counts twice. Source bytes include full filenames and contents without scanning positions.

Admit calls after required argument evaluation and parameter preparation, before copying the signature or entering the callee. An argument's completed effects survive a later call-record rejection. Existing depth/signature checks retain their earlier order. Admit handler errors before building Catch metadata or installing the temporary binding. Measure admitted per-tree diagnostics without copying strings; reserve all aggregate dimensions and source references atomically with checked arithmetic. Failure consumes no capacity.

Quota failure returns BW8001 and latches the requesting Context, bypassing Catch. Rejected handler storage preserves the original category, bounded byte-location evidence, and explicit omissions using the independent [emergency representation](diagnostic-ownership.md#owned-admission-and-emergency-evidence). Observe cancellation/deadlines before attempting admission; a stopped handler retains its original error as bounded evidence beneath the control failure.

## Sharing and Release

Context clones and isolated module contexts share immutable call records. Context clones also share stored handler errors. Their reservations remain charged until the last record owner disappears. Source charges release after the last record referencing that allocation disappears. Separate Engine runs have independent trackers; Context clones share live capacity while keeping independent stop/work state, and module execution shares both.

[Snapshot admission](snapshot-limits.md) counts each copied call/handler handle as an entry. Infallible host Clone stays outside snapshot-work admission. Sharing payloads avoids repeating signature strings, cause trees, and source records for each snapshot; it does not bound the number of host copies.

Release calls and handlers on normal completion, return, error, and observed stop. Restore prior Catch bindings after handler failure. When an error leaves a handler, move uniquely owned metadata into the outgoing diagnostic without requiring another record. If a Context snapshot still owns the record, admit the complete copied tree while its shared reservation stays live. Rethrow also requires copy headroom and includes the new `rethrow` related location and source in admission before copying either payload. For a single stored error with no active calls, rethrow therefore requires two records even though the surrounding handler later releases its original.

An internal outgoing-error carrier keeps each retained or copied record's reservation through expression/statement/call unwinding, imports, cancellation wrapping, and Engine result export. All six aggregate dimensions are reserved atomically, with distinct source owners deduplicated across the original and copy. The prospective copied tree must also fit individual diagnostic limits. Copies share immutable error/source identities while independently owning mutable metadata. Concurrent Context clones compete for the same copy headroom, and only the requester latches a quota failure. Observe cancellation before copy admission.

On rejected rethrow admission, summarize the borrowed original directly; do not clone it to construct the summary. Preserve its category and byte evidence and count the omitted new related site. On rejected handler-unwind copying, preserve the new primary handler failure as bounded evidence and count the omitted original cause. An outgoing error with the same immutable error identity already contains the rethrow evidence and needs no duplicate cause copy. Existing emergency errors increment omitted-cause evidence without copying the retained tree.

## Outgoing Ownership and Handler Re-entry

Moving a retained tree into an outgoing cause transfers its reservation too; cause attachment consolidates the complete combined tree into one record before growing the cause vector. Moving a copy out of Rethrow retains the copy reservation after its original handler disappears. These records stay charged while the internal error is alive, including when another Context clone is executing. Mapping the diagnostic through source/call admission preserves those reservations; a bounded emergency replacement disposes the original metadata before releasing them. Discarding an internal error uses iterative disposal, including raw host trees that have not yet passed individual admission.

When an outer Catch stores the complete outgoing tree, replace its prior reservations atomically with one handler record. Measure the complete tree, preserve unrelated live records, and reconcile source-reference counts before committing any changes. Existing reservations provide capacity for the transferred payload; no artificial duplicate-record headroom is required. Failed replacement leaves old reservations unchanged until the rejected payload is disposed. Source replacements release removed identities before checking new identities, independent of hash iteration order. The merged outgoing tree needs one record. Evaluating `Try { Try { Missing } Catch { Other } } Catch {}` requires two records and two diagnostic nodes at its earlier peak: `Missing` is still retained by the handler when `Other` enters evaluation. Moving and storing their combined tree needs no additional record.

Public statement, program, Pair, and Engine results transfer Diagnostic ownership to the host and release internal charges. Engine retains the carrier through variable-export checking/copying, including failed exports. Public Diagnostic fields, clone behavior, and result types remain unchanged. Holding public results does not retain runtime reservations.

## Outgoing Cause and Related-Location Admission

Internal outgoing errors measure the complete prospective tree before appending a cause or copying an import-related label/span. This applies to handler failures, cancellation wrapping, module initialization, imported calls, and other errors crossing load boundaries. Both individual and aggregate limits apply, including the appended subtree's increased depth. Source identities are deduplicated across both trees and the prospective site. Raw incoming errors acquire their first outgoing reservation at this mutation boundary; already reserved inputs contribute their capacity to one atomic replacement. Moving a cause needs no duplicate payload headroom. Unrelated live records remain charged, and concurrent Context clones compete for the same capacity.

Admission precedes the related string copy and vector insertion, or the cause-vector insertion. On rejection, dispose both inputs iteratively before releasing their reservations. Preserve the current primary category and byte-location evidence beneath the limit error; count the rejected site/cause explicitly. Subsequent emergency mutations only increment omission counts. Duplicate error identities still skip cause attachment. Observe cancellation/deadlines before a new quota can latch; an observed cancellation/timeout stays primary when its additional evidence cannot fit. Normal unwinding performs any remaining stop wrapping.

These checks run even when no outer Catch stores the error. For example, with two records and one diagnostic node, `Try { Missing } Catch { Other }` fails with the retained-node limit and bounded `Other` evidence, including one omitted cause. Two nodes retain the full `Other` error with `Missing` as its cause. The earlier original/new-error overlap requires two records; the cause move adds no further record. Likewise, a two-level failing import requires two related locations even if its error goes straight to the host.

This boundary measures ownership present at the mutation point. Synchronous source/call-stack attachment uses the admission described below; initial Context, AST-reporter, and source-prefix constructors use the construction admission described below. The public Diagnostic methods retain their existing host ownership contract.

## Evaluation Context Admission

Synchronous expression, statement, call, native-result, program/Pair, and Engine result boundaries now reserve the complete outgoing tree, including a prospective innermost span, expression label, and call snapshot. Individual measurement and aggregate replacement happen before copying signatures/vectors or installing the new span reference. Existing spans and call snapshots survive outer unwinding unchanged. Repeated admission credits the carrier's existing reservation, so it does not require another record or duplicate source headroom.

This also admits raw errors with no new metadata. A native failure therefore overlaps its still-active call: one call record plus one outgoing record, two call-frame occurrences, and both signature occurrences. For `Fail` returning a Native error with detail `reason`, the exact counts are two records, one diagnostic, two frames, twenty text bytes, and the unique caller source bytes. An enclosing active call adds its own record and signature/frame charges. A shared original-handler copy additionally overlaps the independently reserved new handler error until the combined tree replaces both reservations.

Rejected context attachment retains the borrowed prospective source's bounded filename and byte range, the correct label, and omitted-frame count without capturing the rejected snapshot. Accepted cancellation wrapping measures its primary context and moved cause together before insertion/capture. Observed cancellation/timeout remains primary under quota rejection; a callback's cancellation category without a real stop does not override a diagnostic limit. Disposal and public result transfer refund all outgoing charges.

Context message and AST-reporter constructors reserve their known message/context before this evaluation boundary. Source/syntax guards also reserve their new filename/prefix source before copying. Public Diagnostic methods retain their host-owned contract.

## Initial Context Message Construction

The Context borrowed, formatted, grouped access, declaration-collision, and import-message constructors reserve shared diagnostic ownership before their first full message/context copies. This covers undefined names, runtime guards, numeric/operator errors, argument/return validation, native panics, Log write errors, input name/non-finite errors, entry-file reads, import reads/cycles/exports, and runtime/native registration collisions. Source contents remain shared; the empty diagnostic skeleton and bounded measurement/source-handle scratch are admission overhead.

Construction has two atomic stages. First reserve the complete known node/source/label/related-site/call context, allowing impossible context quotas to reject before full formatting or source-coordinate work. Count all deferred fields under the individual text limit, then extend the same reservation with their combined byte count before allocating any field. The original context reservation remains live while counting, so another Context clone cannot consume its record. Extension credits the earlier reservation and consumes no extra record. Grouped fields all fit together or none of their full strings are built.

If a stop was already observed, measure the stop root, its pending call snapshot, and the entire deferred detail cause together. Both call snapshots count; shared sources count once. An impossible stopped tree rejects before visiting the deferred formatter, preserving bounded primary stop/location evidence and one omitted cause. Ordinary accepted wording, category, labels, sites, and stacks remain intact. Later stops still retain primary control priority during unwinding.

The constructed error keeps its reservation through private callback, operator, input, registry, import, and evaluation paths. Public input/registration APIs transfer raw Diagnostic ownership and release the reservation when returning to the host; Engine input validation uses the internal carrier path. Public result signatures and host callback contracts remain unchanged. Failed grouped admission or a formatter failure releases provisional/final capacity before the fixed emergency error leaves construction. Only the requesting Context latches a quota failure.

## AST Reporters and Source-Prefix Construction

Runtime syntax, control-placement, and duplicate-parameter reporters use the same two-stage shared construction admission. Known source/call/related ownership is reserved before full syntax-excerpt formatting or coordinate scans; all message fields are then admitted together. Private Program, validation, and Pair reporters preserve the outgoing carrier, including through imports and subsequent import-site admission. Standalone Program and native-signature helpers continue to use default individual quotas.

Source/syntax guards create a fresh source owner containing the borrowed filename and checked prefix. Before either copy, reserve the complete diagnostic context plus the new source bytes. These unpublished bytes consume shared source capacity even though no source allocation identity exists yet. Once copied, publish the fresh source identity into the same reservation without releasing bytes or requiring additional headroom. Other live source owners, including equal text in distinct allocations, remain charged. Failed replacement preserves all prior ownership; disposal refunds unpublished bytes too. An observed stop and both pending call snapshots are admitted with the detail cause before copying.

Accepted diagnostics preserve their exact messages and locations. Rejection preserves bounded original resource/syntax/validation evidence, byte offsets, and omitted context; observed cancellation remains primary. Earlier Engine source-size/read checks retain their existing error representation. Parser/AST input ownership and Pest-owned error buffers are separate from interpreter diagnostic construction; rejecting a diagnostic does not eliminate buffers already required for parsing.

AST node/depth/source failures now return borrowed limit/location evidence from the iterative walker. Defensive lowering returns a static failure description, including for arbitrary Pest rules passed through the Pair API. Both reach the Context reporter before message construction or diagnostic source attachment; definition measurement uses that reporter too. Standalone entry points admit the same evidence under default individual limits. Standalone input-origin helpers and NativeOperation keep their separate ownership contracts.

## Synchronous Construction Audit

The remaining direct source attachments in native registry admission, namespace publication, import resource/snapshot checks, and Catch-binding installation now use carrier admission. Native template admission carries the reserved error through Engine export; public registration releases the reservation at its host return. Import resource failures admit their prospective primary span, call snapshot, and related site together, preserving earlier latched resource/control failures and bounded omission evidence. Emergency unwinding adds omitted related-site counts without recapturing call snapshots.

The synchronous audit covers these boundaries:

| Path | Ownership boundary and evidence |
| --- | --- |
| Context-generated messages, AST syntax/control/parameter/limit/lowering failures | Deferred reporters reserve complete known context, then grouped fields before full copies; constructor and AST/Pair tests cover quotas, active calls, borrowed source evidence, clone pressure, and public transfer. |
| Source/syntax prefixes | Reserve new filename/prefix bytes before allocation, publish identity without releasing capacity; pending-source atomicity and allocation tests cover rejection and release. |
| Incoming host errors | Host strings already exist; the first runtime boundary reserves their full tree and prospective metadata before copying. Runtime ownership tests cover deep disposal and call/handler overlap. |
| Rethrow, handler unwind, cause/site/context mutations | Carrier reservations remain live and transfer atomically; no direct mutable-metadata clone bypasses admission. Copy, mutation, import, and handler tests cover overlap, source identity, and cleanup. |
| Context/module snapshots | Share immutable call/handler records and live trackers; snapshot budgets count copied handles. Shared/concurrent Context tests cover pressure and independent stop latches. |
| Public returns and Engine exports | Carriers remain live through export, then release at explicit public transfer. Result-export failures use the separate result-budget contract and fixed source-free error evidence. |

Small fixed resource/stop categories and empty construction skeletons are bounded admission overhead. Their full outgoing context is admitted at the relevant boundary. Setup failures occur before requested local budgets are installed and use default construction limits. Standalone input/signature/operator helpers, public Diagnostic mutation/clone methods, NativeOperation ownership, and host-created error strings keep their documented separate contracts. This audit does not treat them as hidden synchronous Context allocations.

## Scope and Evidence

These are logical retained-record and copy-admission limits, separate from individual runtime-error quotas and temporary Catch-value storage. The outgoing carrier preserves reservations acquired by evaluation admission, handler storage, copies, and metadata/cause mutation admission. The Context and AST-reporter families above also reserve before construction, including their known stop/context/cause ownership and newly allocated source prefixes. AST-limit and defensive-lowering errors also use these construction reservations, including failures before normal evaluation starts. Standalone helper errors retain their separate boundary. Host-retained results, standalone NativeOperation errors, allocator overhead, formatting, and output have separate contracts. These quotas establish neither a process-memory ceiling nor a hard deadline.

Unit and integration checks cover every dimension, overflow/atomicity, concurrent capacity, source identity/lifetime, snapshot sharing/handle charges, nested handlers, complete causes, rethrows, imported calls, argument effects, clone stops, fresh Engine runs, and cleanup. Allocation observations verify rejection before large signature and Catch-detail copies. R19 host corpus cases and an executed Rust example pin handler reservation behavior.

Copy admission adds six unit checks for exact/one-less aggregate dimensions, prospective individual related-site limits, unique/shared ownership, concurrent copies, actual Context snapshot retention, primary-error evidence, duplicate identities, cancellation, and cleanup. Two integration checks cover rethrow headroom, prior effects, restored bindings, repeated caught failures, and independent clone stops. An allocation comparison observes zero additional large metadata copies on rejection and one on accepted rethrow. Two additional R19 cases and an executed Rust example pin the two-record boundary.

Outgoing lifetime coverage adds eight unit checks for atomic merging/replacement, all quota failures and overflow, source identity reconciliation, concurrent Context pressure, import unwinding, cancellation summaries, Engine export failure, public transfer, and 100,000-level raw-error disposal. Existing runtime/handler/CLI/allocation matrices remain active. Two R19 handoff cases pin complete merged-tree admission and rejection; their two-record allowance includes the original/new-error overlap before one-record re-entry.

Mutation admission adds five unit checks for prospective tree/source/depth measurement, every aggregate dimension, exact replacement credits, unrelated ownership, concurrent Context pressure, cancellation priority, omitted metadata, public transfer, and 100,000-level rejected causes. Two integration checks pin uncaught handler failure and nested-import publication without outer Catch admission. Earlier R19 cases, runtime stop/timeout matrices, import construction, snapshot, and ownership checks remain active.

Context admission adds three unit checks for exact prospective location/label/frame measurement, every aggregate quota, borrowed rejection evidence, source release, idempotent re-admission, competing Contexts, and public transfer. Three integration checks cover active-call peak overlap, cancellation with insufficient primary/cause frame capacity, controlled-clock timeout, and unobserved callback cancellation categories. An allocation comparison verifies that rejecting a native error before its snapshot avoids a 64 KiB signature copy. Existing R19 handoff and shared-handler tests now assert the charged outgoing overlap explicitly.

Initial construction adds six unit checks for complete stopped-tree measurement, reservation-before-format ordering, skipped deferred formatters, every aggregate dimension, distinct source release, concurrent Context pressure, publication, late formatter cleanup, and cancellation arriving during formatting with rejected wrapper context. Two integration checks cover eleven runtime families at exact/one-less text limits plus public input/registration transfer and atomic Engine input rejection. An allocation comparison observes zero large copies for rejected borrowed/grouped messages and the expected one/two full strings on acceptance. Existing construction, operation, source/AST, handler, cancellation, and R19/R21 corpus matrices remain active.

AST/source construction adds five unit checks for pending-source replacement, overflow, concurrent capacity, publication, exact live-call overlap, distinct source identities, parser-carrier lifetime, public transfer, and stopped-prefix evidence. Two integration checks cover syntax/control/parameter/guard quotas and imported parser failures with live callers. An allocation comparison covers all four families under shared text/source rejection, distinguishing required parser buffers from skipped diagnostic copies. Existing source/validation/Pair and R19/R21 matrices remain active.

The final synchronous audit adds two unit checks and two public integration checks. They verify borrowed AST failures do not increment source-owner counts, all applicable shared construction dimensions with live calls, reservation transfer and clone pressure, five AST execution entry paths, defensive Pair lowering, and registry-source release. Existing import tests pin earlier snapshot-limit priority; full runtime, handler, operation, allocation, source, and R19/R21 suites remain active.
