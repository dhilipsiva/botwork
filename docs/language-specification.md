# Core Language Specification

Version 1 records the core semantics established by the interpreter refactor. The evidence table names implemented expectations; [language behavior](language.md) provides usage details. Further contracts and conformance work remain in the roadmap. This specification does not claim exhaustive language conformance or achievement of the 9.5+ quality target.

## Evaluation

**E1 — Program execution.** Parse and validate the whole file before executing statements in source order. Syntax errors, invalid control placement, and duplicate parameter labels prevent all execution. Stop at the first uncaught runtime error. Definitions become available when their defining statement executes; they are not hoisted.

**E2 — Expressions.** Evaluate an ordinary binary operator's left operand before its right operand; stop at the first evaluation error. Apply the operator after both values are available. Evaluate array elements and map values in source order. Evaluate an assignment's entire right-hand side before updating its destination. Parentheses change grouping, not operand evaluation order.

**E3 — Calls.** Resolve the complete statement signature before evaluating arguments. Evaluate arguments once, left to right, in the caller's environment. Only after all arguments succeed, create the invocation frame and bind its parameters. A failed argument must not install any parameter bindings. Completed argument effects are not rolled back. Native statements follow the same argument-order contract.

**E4 — Boolean selection.** Conditions require booleans; numbers, strings, collections, and `None` have no implicit truthiness. For `and`/`or`, evaluate and require a boolean left operand first. `false and rhs` yields `false`; `true or rhs` yields `true`, without evaluating or checking the type of `rhs`. Otherwise evaluate `rhs` and require a boolean. Both branches must still be syntactically valid.

**E5 — Call composition.** `@{ Sentence |argument| }` is a primary expression enclosing exactly one call. Use ordinary signature lookup, typed argument validation, lexical scope, result, and diagnostic rules; allow nested calls and postfix access without changing operator precedence. Evaluate selected calls once in source order, and skip unselected boolean calls. Resolve a call before running any argument effects; first failure skips remaining work without rolling back completed effects. Collection access retains its base snapshot before effectful keys. Reject empty/multiple/statement-containing forms before execution. [Composition rules](language.md#calls-inside-expressions) define delimiters, layout, and failure behavior.

## Values and Operators

**V1 — Value kinds.** Values are `None`, boolean, signed 32-bit integer, finite 32-bit float, Unicode string, ordered array, or map with string keys. An absent variable is an error, distinct from a variable bound to `None`. `None` represents no returned value; no source literal for it is currently defined. Strings follow the [decoding rules](language.md#strings). Arithmetic follows the [checked numeric contract](language.md#arithmetic-boundaries-and-errors); the full signed literal range follows [signed integer conversion](language.md#signed-integer-literals).

**V2 — Grouping.** Binary precedence, weakest first: `or`; `and`; `==`/`!=`; `<`/`<=`/`>`/`>=`; `+`/`-`; `*`/`/`/`%`; `^`. Each level associates left except power, which associates right. Comparisons are ordinary binary operations, not mathematical chains: `1 < 2 < 3` attempts to compare a boolean with an integer and fails. Unary `-` and `!` bind above multiplication and below a power to their right. Negative exponents and repeated prefixes are allowed: `-2 ^ 2` is `-4`, `2 ^ -2 ^ 2` is `0.0625`, and `!!true` is `true`. [Power rules](language.md#powers-and-unary-operators) include checked intermediate results.

**V3 — Literal collection paths.** Resolve the base variable lexically, then read each parsed segment left to right. Map keys preserve exact spelling; arrays use nonnegative ASCII decimal indexes with bounds checks. Missing bases are variable errors; missing keys, invalid indexes, and non-collection traversal are catchable access errors identifying the first failing segment. Return the selected value without modifying the container. None-valued entries are present. [Access rules](language.md#collection-access) define literal/computed composition and reject indexed assignment.

**V4 — Computed collection reads.** Access is postfix and binds before power/unary operations. Evaluate its variable, literal, call, or grouped base once and retain that snapshot across computed keys. Visit segments left to right; evaluate each bracket expression once before validating its receiver/key types and performing lookup. Arrays require nonnegative integer values; maps require exact strings. No implicit conversion occurs. Stop on the first evaluation or lookup error before visiting subsequent keys. Brackets and dot segments freely compose. Map literals accept identifier and quoted string keys; decode quoted keys with ordinary string rules. Reads return independent values; updates will be library operations returning replacements, with no indexed assignment syntax.

**V5 — Precision and numeric comparison.** Integer values are exact `i32`; decimal float literals round to binary32 with ties to even. Mixed arithmetic and division first convert integer operands to `f32`; floating powers use the previously specified wider intermediates. Compare numeric values by exact widening to `f64`, without arithmetic-style integer rounding. Equality has no tolerance; both signs of zero compare equal. Ordering accepts numbers only. [Precision rules](language.md#numeric-precision-and-comparison) define conversions, boundaries, and examples.

**V6 — Structural equality.** Equality/inequality accept all finite value kinds. Numbers compare by V5; booleans and strings by exact value; None equals only None. Arrays compare corresponding elements and length; maps compare exact key sets and associated values independently of entry order. Apply these rules at every depth; different nonnumeric kinds are unequal. Evaluate both operands completely before comparison. Validate all nested host-supplied floats before any equality result; non-finite values raise arithmetic errors even if other values or collection shapes differ. Inequality is equality's exact complement. [Value equality](language.md#value-equality) records the intentional change from prototype type errors.

**V7 — Supported operations and ownership.** The [operator matrix](language.md#values-and-supported-operations) defines supported kind combinations and result kinds. Unsupported combinations raise type errors; access has its own failure category. There is no truthiness, implicit string/boolean conversion, or collection ordering. Collection reads, argument/return values, and assignment copies share no mutable value storage. Concatenation returns a replacement; indexed assignment is invalid. Map literals evaluate all entries in source order and keep the last value for each exact decoded key, without suppressing failures in overwritten entries. Map iteration order is unspecified, direct map For iteration is unsupported, and display sorts keys. The [ownership/order rules](language.md#collection-ownership-and-map-order) consolidate these guarantees.

## Lexical Layout

**L1 — Whitespace and statements.** ASCII spaces/tabs are syntax whitespace; LF/CRLF are line endings. Expressions, collections, fixed assignment/control tokens, and block braces may span lines. Arrays/maps allow trailing commas but require separators. Custom sentence text ends at a newline unless an explicit backslash continuation joins the next part/parameter. Bare Return ends at its line boundary unless its value is explicitly continued. Newlines can precede an attached Else/Catch. [Layout rules](language.md#whitespace-lines-and-comments) define boundaries, unsupported bare CR, and reserved delimiters.

**L2 — Comments and strings.** A single/double hash begins a line comment; triple hash exclusively opens a required, non-nesting block comment. Comments separate complete tokens. Unterminated block comments and split operator/keyword tokens are syntax errors. Delimiters/comment markers inside strings are literal. String escaping follows V1; literal newlines retain their original bytes. Empty/comment-only files are valid. Full parsing still precedes all effects.

**L3 — Statement signatures and declarations.** Strip ASCII spaces/tabs from sentence parts and lowercase each remaining Unicode character; preserve punctuation and other whitespace. Parameters are positional placeholders independent of their labels. Matching performs no Unicode normalization or full case folding. Register definitions only when executed; reject an occupied signature in the current frame with both original/conflicting locations, preserving the original. Parent-frame shadowing is allowed. Native initialization fills only vacant slots. Duplicate exact parameter labels are whole-program validation errors; variables and parameters otherwise retain case-sensitive spelling. [Naming rules](language.md#statement-signatures-and-definition-collisions) specify runtime versus validation failures and native-origin reporting.

**L4 — Unicode authoring.** Source is UTF-8. Identifiers start with Unicode `XID_START` or `_` and continue with `XID_CONTINUE`, including combining marks. Names, strings, and keys retain exact code points; variables/parameters/keys are case-sensitive. Sentence matching follows L3 without normalization. Control keywords, boolean literals/operators, numeric digits/decimal point, and delimiters remain fixed as documented. Unicode numeric dot segments retain exact map-key spelling; array indexes remain ASCII. Display preserves combining marks while escaping controls. [Multilingual rules](language.md#multilingual-authoring) specify examples, whitespace, and source-column units.

## Bindings and Definitions

**S1 — Lexical lookup.** Each run has its own outer frame. Each custom invocation gets fresh parameter and local bindings. Read a variable or statement from the current frame, then the defining environment of the currently executing custom statement and its lexical ancestors. Script-level lookup uses the run frame. Bindings are read when used, not snapshotted when a definition is declared. A caller's unrelated private locals are not visible to its callee. Nested statement definitions belong to the defining invocation and disappear when that invocation finishes; statements are not first-class returned values.

**S2 — Assignment and lifetime.** Assignment writes the current invocation or run frame, shadowing an outer variable without changing it. `If`, `While`, and `Try/Catch` bodies share their enclosing frame. Discard invocation locals on normal completion, return, or error; recursive calls get distinct frames. Completed changes in the frame where `Try` executes remain after a caught error.

**S3 — Loops.** `For` evaluates its array once, then visits its values in order. Its iterator is a temporary binding in the current frame. On completion, break, return, or error, restore that frame's previous binding, or remove the temporary binding if none existed there; an inherited binding becomes visible again. Empty iteration leaves bindings unchanged. Other body assignments use the enclosing frame. `While` evaluates its boolean condition before every iteration. `Continue` starts the next iteration; `Break` exits the nearest loop in the same invocation.

## Completion and Return Values

**C1 — Control transfer.** Normal completion, `Return`, `Break`, `Continue`, and evaluation failure are distinct outcomes. Propagate a return through every nested block to its invocation boundary. Consume loop controls only at their nearest enclosing loop. A callee cannot break or continue its caller's loop. `Return` requires a custom-statement body; `Break`/`Continue` require a loop in that same body or at script level. Reject invalid placement during validation, including inside unused definitions.

**C2 — Results.** `Return |value|` returns exactly that evaluated value. Bare `Return` and normal custom-statement completion return `None`; trailing or unreachable statements cannot change the result. Assignment returns its assigned value; native `Log` returns its logged value. Definitions and normally completed control constructs return `None`. Blocks and loops do not accumulate implicit result arrays. No pending control outcome may survive an invocation boundary.

The library's program evaluator returns the final top-level statement's normal result, or None for an empty program. This does not create an implicit return from custom-statement bodies; those require explicit Return for a value.

## Errors and Recovery

**F1 — Catchable failures.** Undefined variables/statements, duplicate runtime statement registration, incompatible values, numeric conversion/overflow, collection lookup failures, and output failures are runtime errors. `Try` with a `Catch` (and optional `Finally`) invokes that handler once after a body error. A handler error propagates outward. `Return`, `Break`, and `Continue` bypass handlers. An error while evaluating a return expression remains catchable because no return value has been produced yet. Duplicate parameter labels in the directly parsed script are validation failures before execution and cannot be caught there; imported-file validation follows M1.

**F2 — Effects and reporting.** Error handling does not undo completed assignments or output. A failed direct assignment preserves its destination; a failed output operation may already have written bytes. Syntax/validation errors in the directly parsed entry script cannot be caught by that script; imported-file loading follows M1. Successfully handled errors exit with CLI status `0`; uncaught failures exit with `1` and diagnostics on stderr. Normal `Log` output uses stdout. Numeric conversion errors remain runtime errors despite the prototype's `ParsingIntegerError` name.

**F3 — Diagnostic context.** Detailed parsing/execution APIs and the CLI retain the innermost relevant source span, original error category, related declaration locations, and an innermost-first snapshot of entered calls. Capture stacks before unwinding so caught errors retain their original callers. Unresolved calls and argument failures add no unentered callee frame. A failed handler preserves its own error as primary and the handled error as a structured cause; successful handling consumes the error. Each error/cause has a stable category code and repair guidance; existing codes are never reassigned. Render start/exclusive-end scalar positions, preserving original UTF-8 byte ranges. Syntax/validation diagnostics still precede effects. Legacy Rust entry points retain category-only errors with code accessors. [Diagnostic fields and compatibility](diagnostics.md) define source ownership, position units, and rendering.

**F4 — Catch inspection and rethrow.** `Catch |name|` optionally binds an owned diagnostic map only while the handler runs. Restore the prior current-frame value or absence on normal completion, loop controls, returns, or errors; an inherited value becomes visible again. Metadata includes code/message/help, category details, source ranges, call frames, related locations, and causes. Source coordinates are exact decimal strings. Bare, case-insensitive `Rethrow` raises the active handler's original diagnostic, retaining its identity, code, span, stack, and causes while recording the rethrow site. Changing the metadata binding cannot change it. An inner Try can catch a rethrow; rethrowing the same error adds no self-cause. Reject Rethrow outside a lexical Catch in the same invocation before effects, including unused nested definitions. [Catch details](language.md#catch-details-and-rethrow) define the binding lifetime and metadata schema.

**F5 — Native invocation.** Register a complete header with valid, distinct parameter labels before use; reject invalid headers and collisions without replacing prior entries. Native and DSL calls resolve and validate arity before evaluating finite arguments once in caller order. Invoke a native callback only after all arguments succeed. Accept every owned finite return kind, including None; reject nested non-finite results before assignment. Preserve typed callback errors with call context; unwinding panics become BW4003. Catch/rethrow and language cleanup apply normally; host effects are not rolled back. Context clones share callback captures and copy DSL bindings. [Native registration](interpreter-architecture.md#register-native-statements) defines host obligations and recovery limits.

**F6 — Shared signatures.** Native and DSL entries expose the same normalized header, parameter names/kinds, return kinds, origin, and error documentation. Untyped DSL kinds are Any and dynamic errors are not inferred. Native declarations can constrain top-level kinds without coercion; evaluate and validate each argument in order before entry, rejecting mismatches at that argument with BW3003 and skipping remaining arguments. Validate returned kinds before publishing a value; preserve the destination and include the entered call on failure. Finite checks remain recursive. Metadata queries/help use the actual visible registry and lexical shadowing, never callbacks. [Signature metadata](interpreter-architecture.md#shared-signature-metadata) specifies builders, declared errors, and completion/hover API boundaries.

**F7 — Async host operations.** Native operations share signature/value/diagnostic contracts and accept owned arguments with cancellation/deadline control. Check stop requests before entry; child cancellation cannot stop a parent or extend its deadline. Drop cooperative async futures on stop, and bound blocking admission while draining started workers for at most the control's stop grace before returning cancellation/timeout; abandon workers that outlive it with a BW5003 cause. Preserve drain errors as causes and completed effects as completed. Host-drop and uncooperative work have the explicit limits in the [async operation contract](interpreter-architecture.md#async-operation-contract). DSL integration and synchronous compatibility follow F8.

**F8 — Asynchronous DSL execution.** Registered NativeOperation calls suspend the shared interpreter in ordinary sentence/expression syntax. Preserve argument/effect order, lexical frames, module initialization/cache/publication, handlers, call context, and run-local budgets across suspension. Each Engine async future owns fresh mutable state; the low-level async API consumes its Context. Propagate run control to operations, release suspended state on drop, and yield periodically during CPU work. Synchronous entry points reject operation registrations with BW5003 before statement effects. The CLI uses the async driver. [Execution rules](async-execution.md) define owned entry points, timeout start, shared host captures, result admission, cleanup, and execution boundaries.

**F9 — Blocking I/O isolation.** Async Engine filesystem/environment preparation, source/import reads and path resolution, ordinary native callbacks, Log, and debug output must leave the executor available to other runs. Use bounded worker admission with owned arguments/results and child controls; retain capacity through delivery or disposal and drain started jobs on normal stops within the [stop grace](shutdown.md). Keep mutable DSL state in the run, admit copied call-frame handles before worker entry, preserve diagnostic causes and prior assignments, and retain synchronous API thread behavior. CLI source/input preparation also runs off the executor. [Worker rules](nonblocking-io.md) specify pool sizes, scheduling/backpressure, resource ownership, callback thread changes, and the limits of syscall cancellation and shutdown.

**F10 — Owned cleanup.** Try requires Catch, Finally, or Catch followed by Finally. Each entered Try/Finally owns cleanup that runs once after normal completion, returns, loop controls, handled/unhandled errors, and cooperative stops. Nested owners unwind in reverse order; locals remain available. Cleanup cannot escape through Return/Break/Continue/Rethrow into an enclosing scope. Preserve the original failure when cleanup also fails, attaching bounded secondary evidence. Each ordinary owner receives independent cleanup steps and a deadline; new owners entered during cleanup share that allowance. Retention and cumulative work quotas remain shared. Await cooperative cleanup; dropping futures or terminating the host does not execute it. [Cleanup semantics](cleanup.md) define partial acquisition, cancellation, quotas, and failure limits.

**F11 — Bounded polling and retries.** `Eventually` observes a condition and requires `timeout_ms`; `Retry` repeats an action and requires `attempts`. Validate the strict options Map before the block runs. Attempt 1 starts immediately, and each later attempt starts `min(interval × backoff^(n−1), max_interval)` milliseconds after the previous failure. No attempt starts at or after the deadline, and the deadline cooperatively interrupts an attempt in progress. Attempts share run steps and quotas but latch their own stops. Catchable failures and attempt-local operation timeouts end only the attempt; run cancellation, run deadlines, and resource limits propagate. Eventually retries every attempt failure. Retry repeats a BW5002 timeout only when `retry_on` lists it, and `retry_on` otherwise restricts which codes are retried. An unretried failure propagates unchanged. Exhaustion raises catchable BW9004 or BW9005 at the header with the attempt count, a bounded JSON history, and the last failure as its first cause. Break, Continue, and Rethrow cannot leave an attempt; Return completes it. Polling requires asynchronous execution. [Polling semantics](polling.md) define options, scheduling, and evidence.

## Modules

**M1 — Local imports.** Import a literal local .botwork path under an identifier namespace, resolving it against the importing source. Canonical identity controls caching and active-cycle detection. Parse/validate before module initialization, isolate module globals/helpers, and publish a complete namespace only after success. Cache successful dependencies even if a parent fails; preserve completed effects. Qualified calls retain caller argument order and module lexical scope. Reject same-scope namespace collisions before loading, preserve originals, and shadow complete parent namespaces locally. Importer handlers may catch ordinary loading failures with original codes/spans/import context. [Local module semantics](language.md#local-modules) specify exports, UTF-8 paths, cache/cloning, retries, and limitations.

## Inputs

**I1 — Input variables.** Validate files/settings before entry-script effects, using exact DSL names and JSON-to-value conversions. Apply files in order, then flags in order, replacing whole bindings. Install in the root scope; preserve lexical shadowing and module isolation. Reject malformed/range/non-finite/depth/file failures with BW7001. Rust installation is atomic across all supplied names/values. [Input rules](input-variables.md) define numeric token kinds, duplicate keys, JSON depth, path resolution, failure priority, and CLI status.

## Embedded Execution

**R1 — Embedded runs.** Engine execution starts with fresh DSL/module state and validated per-run variables, a resolved directory, and an immutable environment overlay without changing host globals. Reuse registered natives and owned programs; explicitly share callback captures only. Return an owned result/diagnostic, completed root bindings, consumed steps, and elapsed time. Check cancellation/deadlines and configured source-byte/step/call-depth budgets at documented boundaries; share counters across imports. Latched run stops bypass handlers while preserving interpreter cleanup and completed effects. [Embedded-run rules](embedded-runs.md) define defaults, counting, stop priority, clocks, file reads, concurrency, legacy compatibility, and remaining resource/termination limitations.

## Source Bounds

**R2 — Source preflight.** Bound source bytes, open delimiters/active Else-If links, expression operators, and their combined complexity before recursive parsing/lowering. Ignore strings/comments according to their lexical context; sentence quotes never hide nested argument syntax. Apply local guards to public Pest parsing, Program, CLI source loading, native headers, and module sources. Report structured BW8001 from detailed APIs, retaining a bounded UTF-8 prefix, and reject configuration above fixed syntax ceilings. [Syntax limits](syntax-limits.md) define exact counts, defaults, compatibility, and remaining host-AST/runtime limits.

## Runtime Bounds

**R3 — Shared runtime budgets.** Apply default step/call limits, combined evaluation depth, active import depth, and parser-entry stack headroom to Engine, CLI, and Context execution. Configure limits locally; reject unsupported ceilings before effects. Count active statements, expressions, and dispatch wrappers together, including re-exports. Share budgets across imported contexts; persist counters across low-level evaluations. Release depth guards and restore temporary bindings during unwinding. Latched resource/cancellation/deadline stops bypass Catch. [Runtime rules](embedded-runs.md) define exact defaults, counting, CLI flags, cloning, cooperative deadlines, and remaining aggregate/host limits.

## Owned Syntax Bounds

**R4 — Tree admission.** Check all reachable owned syntax before recursive control validation or effects. Bound node count/depth and individual/aggregate source owners, including host-reassembled programs and unreachable bodies. Count shared source allocations once and repeated syntax occurrences individually. Use an iterative walk with width-independent pending work. Apply configured budgets to Engine/Context/module/Pair entry points and defaults to Program/CLI entry points; report BW8001 or unsupported-configuration BW7002. [AST rules](ast-limits.md) define exact counts, public configuration, source identity, diagnostic locations, and remaining allocation/aggregate-state limits.

## Import Bounds

**R5 — Import admission.** Share cumulative load/source/path/binding/metadata budgets across module initialization and calls. Bound reads before decoding/parsing, retain charges for failed work, and reuse cached sources without another load. Check cached dependency depth as well as pending ancestors; atomically admit namespace/export publication before copying metadata. Preserve completed initialization effects and dependencies on late failure while publishing no partial namespace. Latch BW8001 across handlers and reject unsupported graph ceilings with BW7002. [Import limits](import-limits.md) define counts, defaults, ordering, aliases, zero/clone behavior, and remaining memory/host limitations.

## Value Bounds

**R6 — Value admission.** Bound each explicit value's nodes, depth, string/key bytes, container entries, and total payload. Apply local admission at root input, native/operation argument/result, expression-result, Catch-binding, and operator boundaries. Validate all root inputs before installation; latch Context/Engine resource stops and retain cancellation priority. Release rejected owned host data iteratively, including early failures and unpolled operations. Preserve interpreter cleanup and original failures when Catch binding admission fails. [Value rules](value-limits.md) define exact accounting, defaults, public APIs, implicit None completion, finite/kind validation, ownership, and remaining preallocation/aggregate limits.

## Value Construction Bounds

**R7 — Construction admission.** Check decoded strings and borrowed values before copying. Preflight concatenated results after ordered operand evaluation; reuse owned storage without cloning array elements. Check known array width/minimum shape and distinct map keys before child effects or container allocation. Admit each required child's metrics before parent insertion, replace duplicate-key node/payload contributions, and stop before later children on failure. Keep all duplicate value effects in source order and preserve previous assignments on rejection. [Construction rules](value-limits.md#checks-before-construction-and-copying) define resource-failure priority, temporary-value scope, allocation evidence, and remaining aggregate/input bounds.

## Input Bounds

**R8 — Input admission.** Bound each encoded source and cumulative bytes/source count/raw tokens/root names across ordered input loading. Check file length before decoding; preflight raw JSON nesting, array shape, and decoded string/key bytes (including Unicode escapes) before allocation. Keep bounded raw visitors and last-key-wins conversion; admit child metrics before inserting decoded values. Apply the default value-depth ceiling during parsing while retaining the separate raw nesting guard for discarded data. Preserve file-then-flag overrides, exact numbers, bounded origin/path diagnostics, BW8001 resource failures, and BW7001 semantic errors. [Input budgets](input-variables.md#input-resource-budgets) define counts, zero/local configuration, error priority, compatibility, and remaining runtime/host limits.

## Retained Variable Bounds

**R9 — Stored-value admission.** Reserve aggregate live value/node/payload allowance before publishing variable storage and before assignment copies. Count shared storage once across root/call/module frames, cached globals, saved bindings, access snapshots, and public Context clones. Release after the final owner drops; replacements and atomic input batches require peak headroom. Latch requesting-context failures with BW8001, preserve prior bindings, and unwind frames/iterators/handlers reliably. Engine runs start independent trackers. [Retained-value rules](retained-values.md) specify defaults, exact counts, stop/clone behavior, concurrency, and remaining metadata/temporary/snapshot scope.

## Retained Definition Bounds

**R10 — Definition ownership admission.** Bound distinct installed DSL definitions, their AST subtree costs, and unique reachable source text/name bytes across repeated evaluations. Preserve collision priority and earlier registrations/effects; reserve atomically before metadata copies and publication, and latch BW8001 on rejection. Share accounting across modules and Context clones, release on final runtime ownership, and start fresh Engine trackers. [Definition rules](retained-definitions.md) specify identity deduplication, conservative nested-subtree counts, exact defaults, source discovery, concurrency, and remaining metadata/snapshot scope.

## Retained Variable-Name Bounds

**R11 — Variable-name admission.** Bound per-name UTF-8 bytes and aggregate live name counts/bytes before copying new variable keys. Preserve exact identifier identity, reuse existing assignment/input keys, and share names across Context/module snapshots. Atomically admit input batches, unwind call/loop/handler/module ownership, and restore saved names without new admission after a stop. Preserve required RHS effects, previous destinations, Catch causes, independent clone latches, and fresh Engine trackers. ## Retained Registry Bounds

**R12 — Registry metadata admission.** Bound statement/namespace records, descriptor nodes, lookup keys, owned metadata strings, and unique source text/name bytes before publication and owned copies. Preserve collision priority; stage complete imported namespaces atomically after initialization in normalized order. Share immutable metadata across clones/modules and release final-owner reservations. Admit native templates against each fresh Engine run's budgets before inputs/effects; exempt only fixed built-in initialization. Bound borrowed metadata-query result counts and completion normalization without changing spelling rules. ## Frame and Cache Snapshot Bounds

**R13 — Snapshot work admission.** Bound cumulative copied table entries and path bytes before Engine template, module initialization, and imported invocation copies. Atomically check combined charges with overflow protection; include fixed built-ins and each copied occurrence. Captured working-directory errors share their unformatted owner; count a copied error handle as one entry and zero path bytes. Preserve earlier effects and existing state on rejection, skip Catch on the latched stop, and restore invocation/loop/handler state. Rebuild tables from live entries and transfer isolated caches back on all outcomes. Keep infallible host Clone ownership explicit and offer budgeted `Context::try_clone()`. ## Owned Result Export Bounds

**R14 — Engine result admission.** Admit combined terminal/root value counts, nodes, variable-name bytes, and payload bytes before result publication or owned export copies. Count each exported occurrence, including successful None; exclude private/module bindings and failed terminal values. Move unique ownership and copy shared payloads only after admission. On rejection, omit the entire root map and report `snapshot_error`; preserve any earlier execution failure/cancellation as primary, otherwise return the export limit failure. ## Live Temporary Bounds

**R15 — Temporary value admission.** Bound live expression/call/completion roots, recursive nodes, and payload across nested scopes/modules. Reserve static argument slots, collection placeholders/keys, borrowed copies, and concatenation/known Log outputs before allocation; preserve documented operand/output overlap and required-effect order. Transfer child ownership into containers and parameters into storage, retaining iterator/argument reservations for their declared lifetimes. ## Diagnostic Metadata Bounds

**R16 — Diagnostic conversion admission.** Before constructing a Catch binding, measure its complete diagnostic metadata, formatted message/help, cause depth, and source-position scan work; reserve its live temporary allowance before copying. Apply the tighter of diagnostic conversion and ordinary value budgets, preserve the original failure as a cause on rejection, and leave the previous binding intact. Resource failures latch and bypass handlers. Checked host conversion borrows the unchanged original; full infallible conversion remains explicitly host-owned. Preserve exact metadata and coordinate strings without truncation. ## Host Diagnostic Ownership

**R17 — Diagnostic lifecycle helpers.** Measure borrowed diagnostic trees without copying, recursively calling, or formatting text. Bound diagnostic count/depth, call/related counts, raw text, and distinct source-owner bytes before checked cloning. Preserve error/source identities and independently copy mutable metadata. Provide iterative full Clone, explicit disposal, and category extraction for deep host trees; guard runtime-owned abandoned worker errors. ## Runtime Diagnostic Admission

**R18 — Individual runtime errors.** Apply local diagnostic tree/context/text/source budgets through synchronous Engine, Context, statement, Pair, and module execution. Measure prospective call snapshots before copying; preserve existing entered-call context. Latch quota failures and bypass handlers while keeping fixed emergency evidence bounded during further unwinding. Observe cancellation/deadlines before diagnostic limits can replace their priority, preserving cause context when it fits and explicit omissions otherwise. [Runtime diagnostic rules](runtime-diagnostics.md) define defaults, entry/configuration boundaries, emergency behavior, clone semantics, and remaining aggregate/construction/async limits.

**R19 — Retained diagnostic records.** Reserve aggregate active-call and handler-error records, tree/context/text counts, and distinct source owners before call-signature copies or Catch metadata construction/binding. Admit rethrow and shared-handler copies with original/copy overlap before cloning, including new related-site metadata; move unique handlers without another copy. ## Acceptance Tests

**T1 — Named suites and case selection.** Discover only explicit suite paths, in command-line order, and cases in declaration order, before executing any selected case. A suite separates imports/custom definitions in its optional Library block from runnable Case bodies. Require unique stable suite/case IDs independent of paths, display names, tags, and positions. Inherit suite tags and intersect exact case selectors, any included tag, and completed prior-failure IDs; exclude any matching excluded tag without reordering. Reject stale IDs and invalid unselected bodies before effects. Empty selection fails except a completed empty failure record. Each admitted case uses fresh inputs, mutable state, budgets, module initialization, and an admission-time deadline under R32's bounded scheduler. Preserve original source coordinates. Listing produces metadata without execution. Initialize requested failure output as incomplete before discovery/effects and publish complete discovery-ordered failure IDs only after all terminal statuses and summary delivery. Reject incomplete, malformed, oversized, or unsupported records and competing writers. [Suite rules](suites.md) define syntax, metadata/AST/discovery bounds, exact selection semantics, storage publication, and remaining report/fixture/shutdown scope.

**T2 — Parameterized cases and datasets.** Discover literal-only inline or explicitly referenced datasets before any case effects. Every row requires a stable ID and typed value; duplicate/invalid IDs, data syntax, unknown references, and aggregate admission failures stop discovery even for excluded data. Cache immutable canonical data files within CLI discovery, preserving queued values across later file changes. Inherit suite/case/dataset/row tags. [Dataset rules](parameterized-cases.md) specify literal types, paths, binding precedence, limits, metadata, listing, and host resolution.


**T3 — Fixture owners.** Validate optional SuiteSetup, SuiteTeardown, CaseSetup, and CaseTeardown declarations before effects. Retain one context for each selected suite with a suite hook. Export bounded immutable setup inputs into independent cases, with row overrides before copying. Failed suite setup skips unentered cases; shared fixture failure affects all selected IDs and cannot yield a successful run. Bound all active phases by jobs without charging idle owners a work slot. Give cases fresh admission deadlines and optional parent suite deadlines; cleanup uses independent cooperative allowances with shared cumulative quotas. Reporter failure stops admission and drains entered owners. Forced termination and dropped futures do not execute awaited cleanup. [Fixture rules](fixtures.md) define ownership, scheduling, limits, reporting, and host callback obligations.

**T4 — Setup failure and skipped-case policy.** Distinguish unselected cases, selected cases blocked before admission, and admitted cases whose setup or body fails. Interrupted/report-failed execution does not infer outcomes or complete history. **B6 — Process statements.** Provide literal String argument lists, immutable per-run environment inheritance with per-call overlays/removals, child directories, text and binary stdin/stdout/stderr, and exit-code/signal results. Timeouts, cancellation, and resource exhaustion bypass Catch while Finally runs under its cleanup allowance. Async calls use bounded native workers; dropped runs still request supervised group termination and direct-child reaping. Incomplete I/O or cleanup never yields a successful partial result; pending ownership retains capacity and leases. **B9 — Structured data.** `Parse JSON` converts one JSON document with the input-variable rules: i32 Int tokens, f32 decimal/exponent tokens rounded directly, `null` to None, last duplicate key wins, one leading BOM ignored, at most 128 nested containers. Each converted node is admitted to temporary budgets before allocation. `Format JSON` writes compact canonical JSON: map keys in Unicode scalar order, Floats always with a decimal point or exponent in shortest round-trip form, and JSON escapes for quotes, backslashes, and controls. Parsing formatted text restores an equal value with identical kinds. `Parse CSV` reads a header row of nonempty distinct names and RFC 4180 fields with LF/CRLF records into an Array of Maps of Strings.
