# Core Language Specification

Version 1 records the core semantics established by the interpreter refactor. The evidence table names implemented expectations; [language behavior](language.md) provides usage details. Further contracts and conformance work remain in the roadmap. This specification does not claim exhaustive language conformance or achievement of the 9.5+ quality target.

## Evaluation

**E1 — Program execution.** Parse and validate the whole file before executing statements in source order. Syntax errors, invalid control placement, and duplicate parameter labels prevent all execution. Stop at the first uncaught runtime error. Definitions become available when their defining statement executes; they are not hoisted.

**E2 — Expressions.** Evaluate an ordinary binary operator's left operand before its right operand; stop at the first evaluation error. Apply the operator after both values are available. Evaluate array elements and map values in source order. Evaluate an assignment's entire right-hand side before updating its destination. Parentheses change grouping, not operand evaluation order.

**E3 — Calls.** Resolve the complete statement signature before evaluating arguments. Evaluate arguments once, left to right, in the caller's environment. Only after all arguments succeed, create the invocation frame and bind its parameters. A failed argument must not install any parameter bindings. Completed argument effects are not rolled back. Native statements follow the same argument-order contract.

**E4 — Boolean selection.** Conditions require booleans; numbers, strings, collections, and `None` have no implicit truthiness. For `and`/`or`, evaluate and require a boolean left operand first. `false and rhs` yields `false`; `true or rhs` yields `true`, without evaluating or checking the type of `rhs`. Otherwise evaluate `rhs` and require a boolean. Both branches must still be syntactically valid.

**E5 — Call composition.** `@{ Sentence |argument| }` is a primary expression enclosing exactly one call. Use ordinary signature lookup, typed argument validation, lexical scope, result, and diagnostic rules; allow nested calls and postfix access without changing operator precedence. Evaluate selected calls once in source order, and skip unselected boolean calls. Resolve a call before running any argument effects; first failure skips remaining work without rolling back completed effects. Collection access retains its base snapshot before effectful keys. Reject empty/multiple/statement-containing forms before execution. [Composition rules](language.md#calls-inside-expressions) define delimiters, layout, and failure behavior.

## Values and Operators

**V1 — Value kinds.** Values are `None`, boolean, signed 32-bit integer, finite 32-bit float, Unicode string, ordered array, or map with string keys. An absent variable is an error, distinct from a variable bound to `None`. `None` represents no returned value; no source literal for it is currently defined. Strings follow the [decoding rules](language.md#strings). Arithmetic follows the [checked numeric contract](language.md#arithmetic-boundaries-and-errors); the full signed literal range follows [signed integer conversion](language.md#signed-integer-literals).

**V2 — Grouping.** Binary precedence, weakest first: `or`; `and`; `==`/`!=`; `<`/`<=`/`>`/`>=`; `+`/`-`; `*`/`/`/`%`; `^`. Each level associates left except power, which associates right. Comparisons are ordinary binary operations, not mathematical chains: `1 < 2 < 3` attempts to compare a boolean with an integer and fails. Unary `-` and `!` bind above multiplication and below a power to their right. Negative exponents and repeated prefixes are allowed: `-2 ^ 2` is `-4`, `2 ^ -2 ^ 2` is `0.0625`, and `!!true` is `true`. [Power rules](language.md#powers-and-unary-operators) include checked intermediate results.

**V3 — Literal collection paths.** Resolve the base variable lexically, then read each parsed segment left to right. Map keys preserve exact spelling; arrays use nonnegative ASCII decimal indexes with bounds checks. Missing bases are variable errors; missing keys, invalid indexes, and non-collection traversal are catchable access errors identifying the first failing segment. Return the selected value without modifying the container. None-valued entries are present. [Access rules](language.md#collection-access) define literal/computed composition and reject indexed assignment.

**V4 — Computed collection reads.** Access is postfix and binds before power/unary operations. Evaluate its variable, literal, call, or grouped base once and retain that snapshot across computed keys. Visit segments left to right; evaluate each bracket expression once before validating its receiver/key types and performing lookup. Arrays require nonnegative integer values; maps require exact strings. No implicit conversion occurs. Stop on the first evaluation or lookup error before visiting subsequent keys. Brackets and dot segments freely compose. Map literals accept identifier and quoted string keys; decode quoted keys with ordinary string rules. Reads return independent values; updates will be library operations returning replacements, with no indexed assignment syntax.

**V5 — Precision and numeric comparison.** Integer values are exact `i32`; decimal float literals round to binary32 with ties to even. Mixed arithmetic and division first convert integer operands to `f32`; floating powers use the previously specified wider intermediates. Compare numeric values by exact widening to `f64`, without arithmetic-style integer rounding. Equality has no tolerance; both signs of zero compare equal. Ordering accepts numbers only. [Precision rules](language.md#numeric-precision-and-comparison) define conversions, boundaries, and examples.

**V6 — Structural equality.** Equality/inequality accept all finite value kinds. Numbers compare by V5; booleans and strings by exact value; None equals only None. Arrays compare corresponding elements and length; maps compare exact key sets and associated values independently of entry order. Apply these rules at every depth; different nonnumeric kinds are unequal. Evaluate both operands completely before comparison. Validate all nested host-supplied floats before any equality result; non-finite values raise arithmetic errors even if other values or collection shapes differ. Inequality is equality's exact complement. [Value equality](language.md#value-equality) records the intentional change from prototype type errors.

**V7 — Supported operations and ownership.** The [operator matrix](language.md#values-and-supported-operations) defines supported kind combinations and result kinds. Unsupported combinations raise type errors; access has its own failure category. There is no truthiness, implicit string/boolean conversion, or collection ordering. Collection reads, argument/return values, and assignment copies share no mutable value storage. Concatenation returns a replacement; indexed assignment is invalid. Map literals evaluate all entries in source order and keep the last value for each exact decoded key, without suppressing failures in overwritten entries. Map iteration order is unspecified, direct map For iteration is unsupported, and display sorts keys. The [ownership/order rules](language.md#collection-ownership-and-map-order) consolidate these guarantees.

## Lexical Layout

**L1 — Whitespace and statements.** ASCII spaces/tabs are syntax whitespace; LF/CRLF are line endings. Expressions, collections, fixed assignment/control tokens, and block braces may span lines. Arrays/maps allow trailing commas but require separators. Custom sentence text ends at a newline unless an explicit backslash continuation joins the next part/parameter. Bare Return ends at its line boundary unless its value is explicitly continued. Newlines can precede an attached Else/Catch. [Layout rules](language.md#whitespace-lines-and-comments) define boundaries, unsupported bare CR, and reserved delimiters.

**L2 — Comments and strings.** A single/double hash begins a line comment; triple hash exclusively opens a required, non-nesting block comment. Comments separate complete tokens. Unterminated block comments and split operator/keyword tokens are syntax errors. Delimiters/comment markers inside strings are literal. String escaping follows V1; literal newlines retain their original bytes. Empty/comment-only files are valid. Full parsing still precedes all effects.

**L3 — Statement signatures and declarations.** Strip ASCII spaces/tabs from sentence parts and lowercase each remaining Unicode character; preserve punctuation and other whitespace. Parameters are positional placeholders independent of their labels. Matching performs no Unicode normalization or full case folding. Register definitions only when executed; reject an occupied signature in the current frame with both original/conflicting locations, preserving the original. Parent-frame shadowing is allowed. Native initialization fills only vacant slots. Duplicate exact parameter labels are whole-program validation errors; variables and parameters otherwise retain case-sensitive spelling. [Naming rules](language.md#statement-signatures-and-definition-collisions) specify runtime versus validation failures and native-origin reporting.

**L4 — Unicode authoring.** Source is UTF-8. Identifiers start with Unicode `XID_START` or `_` and continue with `XID_CONTINUE`, including combining marks. Names, strings, and keys retain exact code points; variables/parameters/keys are case-sensitive. Sentence matching follows L3 without normalization. Control keywords, boolean literals/operators, numeric digits/decimal point, and delimiters remain fixed as documented. Unicode numeric dot segments retain exact map-key spelling; array indexes remain ASCII. Display preserves combining marks while escaping controls. [Multilingual rules](language.md#multilingual-authoring) specify examples, whitespace, and source-column units.

## Bindings and Definitions

**S1 — Lexical lookup.** Each run has its own outer frame. Each custom invocation gets fresh parameter and local bindings. Read a variable or statement from the current frame, then the defining environment of the currently executing custom statement and its lexical ancestors. Script-level lookup uses the run frame. Bindings are read when used, not snapshotted when a definition is declared. A caller's unrelated private locals are not visible to its callee. Nested statement definitions belong to the defining invocation and disappear when that invocation finishes; statements are not first-class returned values.

**S2 — Assignment and lifetime.** Assignment writes the current invocation or run frame, shadowing an outer variable without changing it. `If`, `While`, and `Try/Catch` bodies share their enclosing frame. Discard invocation locals on normal completion, return, or error; recursive calls get distinct frames. Completed changes in the frame where `Try` executes remain after a caught error.

**S3 — Loops.** `For` evaluates its array once, then visits its values in order. Its iterator is a temporary binding in the current frame. On completion, break, return, or error, restore that frame's previous binding, or remove the temporary binding if none existed there; an inherited binding becomes visible again. Empty iteration leaves bindings unchanged. Other body assignments use the enclosing frame. `While` evaluates its boolean condition before every iteration. `Continue` starts the next iteration; `Break` exits the nearest loop in the same invocation.

## Completion and Return Values

**C1 — Control transfer.** Normal completion, `Return`, `Break`, `Continue`, and evaluation failure are distinct outcomes. Propagate a return through every nested block to its invocation boundary. Consume loop controls only at their nearest enclosing loop. A callee cannot break or continue its caller's loop. `Return` requires a custom-statement body; `Break`/`Continue` require a loop in that same body or at script level. Reject invalid placement during validation, including inside unused definitions.

**C2 — Results.** `Return |value|` returns exactly that evaluated value. Bare `Return` and normal custom-statement completion return `None`; trailing or unreachable statements cannot change the result. Assignment returns its assigned value; native `Log` returns its logged value. Definitions and normally completed control constructs return `None`. Blocks and loops do not accumulate implicit result arrays. No pending control outcome may survive an invocation boundary.

The library's program evaluator returns the final top-level statement's normal result, or None for an empty program. This does not create an implicit return from custom-statement bodies; those require explicit Return for a value.

## Errors and Recovery

**F1 — Catchable failures.** Undefined variables/statements, duplicate runtime statement registration, incompatible values, numeric conversion/overflow, collection lookup failures, and output failures are runtime errors. `Try` requires one `Catch`; its handler runs once after a body error. A handler error propagates outward. `Return`, `Break`, and `Continue` bypass handlers. An error while evaluating a return expression remains catchable because no return value has been produced yet. Duplicate parameter labels are validation failures before execution and cannot be caught.

**F2 — Effects and reporting.** Error handling does not undo completed assignments or output. A failed direct assignment preserves its destination; a failed output operation may already have written bytes. Syntax/validation errors cannot be caught by the script. Successfully handled errors exit with CLI status `0`; uncaught failures exit with `1` and diagnostics on stderr. Normal `Log` output uses stdout. Numeric conversion errors remain runtime errors despite the prototype's `ParsingIntegerError` name.

**F3 — Diagnostic context.** Detailed parsing/execution APIs and the CLI retain the innermost relevant source span, original error category, related declaration locations, and an innermost-first snapshot of entered calls. Capture stacks before unwinding so caught errors retain their original callers. Unresolved calls and argument failures add no unentered callee frame. A failed handler preserves its own error as primary and the handled error as a structured cause; successful handling consumes the error. Each error/cause has a stable category code and repair guidance; existing codes are never reassigned. Render start/exclusive-end scalar positions, preserving original UTF-8 byte ranges. Syntax/validation diagnostics still precede effects. Legacy Rust entry points retain category-only errors with code accessors. [Diagnostic fields and compatibility](diagnostics.md) define source ownership, position units, and rendering.

**F4 — Catch inspection and rethrow.** `Catch |name|` optionally binds an owned diagnostic map only while the handler runs. Restore the prior current-frame value or absence on normal completion, loop controls, returns, or errors; an inherited value becomes visible again. Metadata includes code/message/help, category details, source ranges, call frames, related locations, and causes. Source coordinates are exact decimal strings. Bare, case-insensitive `Rethrow` raises the active handler's original diagnostic, retaining its identity, code, span, stack, and causes while recording the rethrow site. Changing the metadata binding cannot change it. An inner Try can catch a rethrow; rethrowing the same error adds no self-cause. Reject Rethrow outside a lexical Catch in the same invocation before effects, including unused nested definitions. [Catch details](language.md#catch-details-and-rethrow) define the binding lifetime and metadata schema.

**F5 — Native invocation.** Register a complete header with valid, distinct parameter labels before use; reject invalid headers and collisions without replacing prior entries. Native and DSL calls resolve and validate arity before evaluating finite arguments once in caller order. Invoke a native callback only after all arguments succeed. Accept every owned finite return kind, including None; reject nested non-finite results before assignment. Preserve typed callback errors with call context; unwinding panics become BW4003. Catch/rethrow and language cleanup apply normally; host effects are not rolled back. Context clones share callback captures and copy DSL bindings. [Native registration](interpreter-architecture.md#register-native-statements) defines host obligations and recovery limits.

**F6 — Shared signatures.** Native and DSL entries expose the same normalized header, parameter names/kinds, return kinds, origin, and error documentation. Untyped DSL kinds are Any and dynamic errors are not inferred. Native declarations can constrain top-level kinds without coercion; evaluate and validate each argument in order before entry, rejecting mismatches at that argument with BW3003 and skipping remaining arguments. Validate returned kinds before publishing a value; preserve the destination and include the entered call on failure. Finite checks remain recursive. Metadata queries/help use the actual visible registry and lexical shadowing, never callbacks. [Signature metadata](interpreter-architecture.md#shared-signature-metadata) specifies builders, declared errors, and completion/hover API boundaries.

## Deliberately Separate Contracts

Imports, resource limits, and async execution remain separate tasks. The core value contract does not implement the planned collection library, serialization, or cross-language value conversions; those additions must extend the specification and conformance evidence explicitly.

F5 evidence in `tests/native_registration.rs` covers headers, normalized/Unicode calls, duplicate labels, both collision directions, initialization, caller arguments, every return kind, non-finite results, typed errors/causes, panic cleanup, clones, and lexical shadowing. Evaluator checks instrument native argument visits, defensive arity checks, and non-finite host arguments. Host corpus cases and an executed Rust documentation example cover public registration.

F6 evidence in `tests/signature_metadata.rs` covers all 127 nonempty kind sets, 49 argument-kind and 49 return-kind combinations, checked builders, source retention, dynamic DSL metadata, finite values, diagnostic/assignment boundaries, and matching help/completion/hover queries. Evaluator checks exercise lexical metadata shadowing/restoration. CLI help/listing tests, two host corpus cases, and an executed Rust example cover the public consumers.

E5 evidence in `tests/call_composition.rs` covers precedence, nesting, resolution/validation before effects, caller scope, short-circuit selection, collection/base/key order, conditions/loops, recursion, None, Catch/rethrow, Unicode/layout, malformed syntax, owned spans, and Pair compatibility. Unit checks retain collection snapshots across effects and independent cloned bindings. Example `18`, CLI failure fixtures, documentation output, and three corpus cases cover public execution.
